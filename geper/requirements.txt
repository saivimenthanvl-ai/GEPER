# --- Core deep learning / model stack ---------------------------------------
# torch is pinned exactly, not left open, because Evo2's flash-attn
# dependency is compiled from source against a specific torch+CUDA ABI --
# Arc Institute's own current install docs (github.com/ArcInstitute/evo2)
# use this exact torch/CUDA combination:
#   pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cu128
#   pip install flash-attn==2.8.0.post2 --no-build-isolation
#   pip install evo2
# CPU-only development machines (no Evo2) can instead install plain
# `torch==2.7.1` from PyPI -- everything else in this file works identically.
torch==2.7.1
# transformers is pinned to EXACTLY what the shipped image runs (the
# Dockerfile's last-wins `pip install "transformers==4.56.2"`), by human
# ruling 2026-09-11: "The image is what ships, so a requirements file
# demanding a version the runtime doesn't have is a claim about the product
# that the product contradicts." Why the image needs 4.56.2: enformer-pytorch
# 0.8.12 hard-pins transformers==4.56.2 and borzoi-pytorch requires <5 --
# neither runs on 5.x (see the Dockerfile's transformers writeup). This line
# was `>=5.12.1,<6.0.0` until then, a range the image never satisfied.
# tests/test_transformers_pin_matches_image.py fails if the two diverge again.
transformers==4.56.2
accelerate>=1.14.0,<2.0.0

# einops is pinned to exactly 0.8.1 (not left as a loose >=) because Evo2's
# own dependency `vtx` (Vortex/StripedHyena-2, ArcInstitute's model code)

# via `pip show vtx` / pypi.org/pypi/vtx/json, not assumed. A looser pin
# here would still resolve today, but would silently start failing the
# moment vtx's exact pin and some other dependency's floor diverge.
einops==0.8.1

# --- Evo 2 (models/evo2.py) --------------------------------------------------
# Arc Institute's DNA foundation model, replacing Nucleotide Transformer.
# NOT a transformers.AutoModel checkpoint; loaded via the official `evo2`
# pip package. GPU-only (no practical CPU path -- see models/evo2.py);

#

# "evo2_7b_base") additionally needs flash-attn, which itself needs a
# matching CUDA-enabled torch build installed FIRST -- see
# https://github.com/ArcInstitute/evo2 for the exact commands, reproduced
# above. Do NOT `pip install flash-attn` as a normal requirements.txt line:
# it has no prebuilt wheels on PyPI (source-only sdist) and compiles against

# plain `pip install -r requirements.txt` in a fresh/CPU environment cannot
# do safely or quickly. Install it manually per the commands above, then:
# Pinned exactly rather than left as a floor: 0.6.0 is also PyPI's
# current latest release (verified live via pypi.org/pypi/evo2/json,
# 2026-08-27), so this changes nothing about what resolves today -- it
# only stops a future release from silently changing behavior with no
# GEPER-side signal that anything moved.

# IMPORTANT -- checkpoint choice: use GEPER_EVO2_VARIANT=evo2_7b_base (the
# default), NOT plain 'evo2_7b'. Verified against
# https://github.com/ArcInstitute/evo2/issues/208 (open, 2026-03-13): plain
# 'evo2_7b' (the 1M-context release) requires Transformer Engine + FP8 +

# 'evo2_7b_base' (8K context) is the checkpoint that's genuinely usable with
# just torch + flash-attn. See README.md "12. Hardware notes" for the

torchvision==0.22.1

# omegaconf: NOT imported anywhere in GEPER's own code, nor in
# standalone_hyenadna.py (the only file GEPER actually imports from the
# vendored hyena-dna checkout -- see models/hyenadna.py's module
# docstring). It's needed one level down: the official HyenaDNA
# checkpoint (weights.ckpt, loaded via `torch.load(..., weights_only=
# False)` in models/hyenadna.py::_load_hyenadna_checkpoint) was produced
# by the upstream repo's own train.py, a PyTorch-Lightning module whose
# `save_hyperparameters()` call captures its Hydra/OmegaConf config
# object as part of the pickled checkpoint. Unpickling that checkpoint
# therefore imports `omegaconf` to reconstruct the embedded config,
# even though no GEPER or standalone_hyenadna.py source line ever
# writes `import omegaconf` -- confirmed against a real failure
# (`ModuleNotFoundError: No module named 'omegaconf'` at HyenaDNA load
# time) in a clean Docker build that only installs this file, where no
# other package happens to pull omegaconf in transitively. Colab/
# bare-metal runs never hit this because some other already-installed
# package (or a stale environment) had it present already. Unpinned
# upstream (geper/hyena-dna/requirements.txt's own training
# requirements list it as a bare `omegaconf` with no version) --
# pinned here to the current stable release since the checkpoint only
# needs OmegaConf's DictConfig to exist, not a specific version.
omegaconf==2.3.1

# torchaudio is NOT imported anywhere in GEPER's own code (no model here
# does audio processing) -- it is pinned explicitly anyway, exactly like
# torchvision above, purely as a DEFENSIVE measure: several of this
# project's dependencies (rna-fm, evo2/vtx) can pull an unpinned
# `torchaudio` in transitively, and some hosted environments (Colab's
# base image in particular) ship their own pre-installed torchaudio
# build tied to whatever torch version *they* shipped, not the
# torch==2.7.1 this file pins. An unpinned or mismatched torchaudio
# whose compiled extension was built against a different torch ABI
# fails at IMPORT time with `OSError: undefined symbol:
# torch_library_impl` (torchaudio registers custom ops via
# TORCH_LIBRARY_IMPL against the torch C++ API at import) -- and
# because Python import errors are not scoped to the module that
# triggered them, this can surface while importing an unrelated model
# (e.g. ESM2) if anything earlier in the import chain touches
# torchaudio. 2.7.1 is the release paired with torch==2.7.1 in PyTorch's
# own compatibility matrix, exactly the same pairing logic as
# torchvision==0.22.1 above.
torchaudio==2.7.1

# --- MMSplice (pipeline/models/mmsplice/) -----------------------------------
# Splice-effect prediction. tensorflow is the only *new* runtime
# dependency this integration adds -- MMSplice's five pretrained
# submodels are Keras/TensorFlow models, not PyTorch.
#
# IMPORTANT: do NOT `pip install mmsplice` normally / do not add it to
# this file as a plain line. The official `mmsplice` PyPI package pins
# `cyvcf2<=0.30.15`, which has no prebuilt wheel for Python 3.12+ and
# cannot be built from source on 3.12+ (its C extension uses a
# CPython-internal struct field, `PyLongObject.ob_digit`, removed in
# 3.12) -- confirmed by attempting the install directly against this
# project's own Python 3.12 toolchain. `pip install mmsplice` therefore
# fails outright here.
#
# GEPER instead auto-installs `mmsplice` with `--no-deps` at runtime
# the first time it's needed (see
# pipeline/models/mmsplice/loader.py::_ensure_mmsplice_package_files_available),
# purely to obtain the package's bundled, official pretrained `.h5`
# weight files -- it never imports the `mmsplice` package's own Python
# code (which is what pulls in cyvcf2/kipoiseq/pyranges). If you prefer
# to pre-provision this in a Docker image / CI step instead of relying
# on the runtime auto-install, run exactly:
#   pip install tensorflow "mmsplice==2.4.0" --no-deps
# (installing plain `tensorflow` first/separately, since --no-deps on
# the mmsplice line means pip will not pull it in automatically).
#
# THIS FILE IS NOT A VERSION AUTHORITY FOR mmsplice. The 2.4.0 above is
# a suggested pre-provisioning command, not a pin this file enforces --
# per the IMPORTANT note above there is deliberately no mmsplice
# requirement line here, so nothing in this file constrains what the
# runtime auto-install fetches. The two paths can therefore disagree:
# pre-provisioning gives you 2.4.0, the auto-install gives you whatever
# PyPI serves that day.
#
# Which version a given run ACTUALLY used is recorded per run, resolved
# from the installed distribution, in `geper_results.json`'s
# `model_checkpoints.mmsplice.resolved_version` (see
# `pipeline/provenance.py`). Until 2026-09-02 that field instead
# asserted "mmsplice==2.4.0 (pinned, see requirements.txt)" and cited
# this file as its authority -- a pin this file does not contain and,
# above, explicitly tells you not to add.
